# 要求仕様書：従業員管理アプリ（psys_flask）

## 1. システム目的

管理者が従業員情報（社員番号・氏名・パスワード）をWeb上で登録・編集・削除できるシステムを構築し、業務効率化と情報の一元管理を実現する。



## 2. 業務要件

| 要件ID | 要件名 | 内容 |
|--------|--------|------|
| RQ-01 | 従業員情報の一覧表示 | 登録済みの従業員情報を一覧で表示する |
| RQ-02 | 従業員情報の新規登録 | 管理者が従業員情報を新規登録できる |
| RQ-03 | 従業員情報の編集 | 既存の従業員情報を編集できる |
| RQ-04 | 従業員情報の削除 | 不要な従業員情報を削除できる |
| RQ-05 | 入力内容の確認 | 登録・編集前に確認画面を表示する |
| RQ-06 | 削除前の確認 | 削除前に確認画面を表示する |
| RQ-07 | DB接続設定 | 外部ファイル（config.py）でDB接続情報を管理する |
| RQ-08 | UIの分離 | HTMLテンプレートとCSSを分離し、保守性を高める |



## 3. 機能要求

| 機能ID | 機能名 | 詳細 |
|--------|--------|------|
| FN-01 | 一覧表示機能 | `/` にアクセスすると従業員情報をテーブル形式で表示 |
| FN-02 | 新規登録機能 | `/create` で入力 → `/confirm` で登録処理 |
| FN-03 | 編集機能 | `/edit/<id>` で編集 → `/edit_confirm` で更新処理 |
| FN-04 | 削除機能 | `/delete/<id>` で確認 → `/delete_confirm` で削除処理 |
| FN-05 | 入力チェック | HTMLの `required` 属性で空欄を防止（今後サーバー側追加） |
| FN-06 | DB操作 | MySQLに対してSQL文で直接操作（INSERT, UPDATE, DELETE） |



## 4. 非機能要求

| 要求ID | 区分 | 内容 |
|--------|------|------|
| NF-01 | 実行環境 | Windows11 / Python 3.10以上 / MySQL |
| NF-02 | 使用技術 | Flask, mysqlclient |
| NF-03 | セキュリティ | パスワードは平文保存（今後ハッシュ化を検討） |
| NF-04 | 保守性 | テンプレート分離、CSSファイルによるスタイル管理 |
| NF-05 | 拡張性 | JavaScript未使用 → 今後動的UI対応可能 |
| NF-06 | 接続設定 | DB接続情報は `config.py` にて一元管理 |

---

## 5. データ仕様

### employee テーブル

| カラム名 | 型 | 制約 | 説明 |
|----------|----|------|------|
| employee_no | VARCHAR | 主キー | 社員番号 |
| employee_name | VARCHAR | NOT NULL | 氏名 |
| password | VARCHAR | NOT NULL | パスワード（平文） |

---

## 6. 画面仕様（概要）

| 画面名 | URL | 主な操作 |
|--------|-----|----------|
| 一覧画面 | `/` | 従業員情報の表示、編集・削除リンク |
| 新規登録画面 | `/create` | 入力フォーム表示 |
| 登録確認画面 | `/create`（POST） | 入力内容の確認 |
| 編集画面 | `/edit/<id>` | 既存情報の編集 |
| 編集確認画面 | `/edit/<id>`（POST） | 編集内容の確認 |
| 削除確認画面 | `/delete/<id>` | 削除前の確認表示 |

---

## 7. 制約事項

- 使用するライブラリは、Flask、mysqlclientのみとする。
- パスワードは現時点で平文保存。
- 入力チェックはHTML側のみ。
- 管理者のみが利用する前提。



## 8. 今回の依頼には含めないが、ポートフォリオして使用する場合は実装が望ましい機能

- パスワードはセキュリティ強化のため、暗号化方式への変更が望ましい。
- 入力チェックはHTML側のみだが、サーバー側のバリデーションの実装が望ましい。
- 認証機能（ログイン）を搭載。
